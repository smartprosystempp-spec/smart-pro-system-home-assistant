# Smart Pro Access Preflight — QA 0.3.1

**Μόνο για τη φρέσκια δοκιμαστική εγκατάσταση Home Assistant. Ποτέ σε παραγωγή.**

Αυτό το ανεξάρτητο πρόσθετο συνεχίζει το επιτυχημένο live QA 0.2.0.
Η 0.3.1 προσθέτει μια **προαιρετική, εφάπαξ, ελεγχόμενη** δοκιμή της
δυνατότητας Home Assistant να δημιουργεί και να διαγράφει χρήστη μέσω Core.

### Τι κάνει (και τι δεν κάνει)

- Ελέγχει ξανά ότι ο συνδεδεμένος χρήστης είναι πραγματικός διαχειριστής μέσω Supervisor Ingress **και** ανεξάρτητης ανάγνωσης του Home Assistant Core.
- Εμφανίζει φόρμα μόνο στον επιβεβαιωμένο διαχειριστή. Το άνοιγμα της σελίδας **δεν εκτελεί καμία αλλαγή**.
- Με ρητή πληκτρολόγηση της λέξης **ΔΟΚΙΜΗ** και υποβολή ενός μοναδικού, βραχύβιου token, δημιουργεί προσωρινό μη-owner διαχειριστή με όνομα `Smart Pro QA TEMP NO LOGIN …`, **χωρίς username, password ή credentials**. Επαληθεύει και ζητά την άμεση διαγραφή του, μετά επιβεβαιώνει ότι δεν υπάρχει.
- Δεν δημιουργεί διατηρήσιμη πρόσβαση Smart Pro, δεν στέλνει δεδομένα στο Portal, δεν αγγίζει Managed Support, Smart Pro Tools ή Tunnel και **δεν αποθηκεύει κανέναν κωδικό**.
- Διαθέτει `homeassistant_api: true` επειδή πρέπει να ελέγξει τις προστατευμένες Core εντολές. Δεν αποτελεί production capability.

### Πρώτο live QA — διαβάζουμε, δεν γράφουμε ακόμη

1. Ενημέρωσε **μόνο** το Smart Pro Access Preflight — QA **0.2.0 → 0.3.1** στο δοκιμαστικό Home Assistant.
2. Κράτησε Start on boot, Watchdog και Auto update **OFF**. Άνοιξε το πρόσθετο ως διαχειριστής.
3. Αναμένεται «Διαχειριστής Home Assistant — επιβεβαιώθηκε και από το Core» και **νέα ενότητα δοκιμής** με πεδίο επιβεβαίωσης.
4. **ΜΗΝ πληκτρολογήσεις ακόμα «ΔΟΚΙΜΗ» και ΜΗΝ πατήσεις το κουμπί.** Στείλε screenshot για να επιβεβαιώσουμε την οθόνη πριν εκτελέσουμε το πραγματικό write test.
5. Ως `Smart Pro QA User` (`smartpro_qa_user`, μη διαχειριστής) εξακολουθεί να εμφανίζεται μόνο «Δεν επιβεβαιώθηκε διαχειριστής», χωρίς φόρμα.

### Δεύτερο checkpoint — ΜΟΝΟ μετά από ρητή συνεννόηση

- Από τον διαχειριστή, πληκτρολόγησε `ΔΟΚΙΜΗ` και πάτησε **μία φορά** «Έγκριση ελεγχόμενης δοκιμής».
- Αναμενόμενο result code: `qa_account_created_verified_deleted`.
- **Σε κάθε περίπτωση**, έλεγξε **Ρυθμίσεις → Άτομα → Χρήστες**, ώστε να επιβεβαιώσουμε ότι δεν υπάρχει χρήστης με όνομα που αρχίζει `Smart Pro QA TEMP NO LOGIN`.
- Αν υπάρχει, **μην επαναλάβεις τη δοκιμή**. Είναι πιθανό η δημιουργία να ολοκληρώθηκε και η διαγραφή να διακόπηκε. Κατάγραψε το αποτέλεσμα και ζήτησε στοχευμένη οδηγία για χειροκίνητη ανάκληση του **συγκεκριμένου** QA λογαριασμού, χωρίς να αγγίξεις άλλους χρήστες.
- Αν εμφανιστεί οποιοδήποτε άλλο result code, μη συνεχίσεις. Δεν κοινοποιούμε cookies, URL ingress, token ή άλλα μυστικά.

### Προστασίες

- Exact Supervisor source peer, headers ταυτότητας, fresh Core `config/auth/list` readback.
- Same-origin POST, 180-second one-time approval bound to HA admin identity, typed confirmation and anti-replay.
- Max **μία ενέργεια** ανά εκτέλεση εφαρμογής. Πριν από οποιαδήποτε νέα προσπάθεια ελέγχεται Core για υπολειπόμενη QA εγγραφή.
- Εντολές Core περιορισμένες σε `config/auth/list`, `config/auth/create`, `config/auth/delete`. Δεν καλείται provider credential creation.
- Αν ο λογαριασμός δημιουργηθεί αλλά το Home Assistant χαθεί/κλείσει στη μέση, δεν μπορούμε να εγγυηθούμε αυτόματη διαγραφή. Απαιτείται ανθρώπινος έλεγχος.

### Rollback

Σταμάτησε το ανεξάρτητο QA πρόσθετο, κρύψε το από την πλαϊνή μπάρα και μην ενημερώσεις κανένα από τα υπάρχοντα πρόσθετα. Αν μετά τη δοκιμή παραμείνει QA account, αντιμετώπισέ το χωριστά με βάση την ακριβή ονομασία του. Το Portal και τα production add-ons παραμένουν ανέπαφα.

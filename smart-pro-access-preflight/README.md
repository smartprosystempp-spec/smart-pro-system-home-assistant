# Smart Pro Access Preflight — QA 0.3.2

**Ελεγχόμενη διαγνωστική έκδοση μόνο για το test Home Assistant.**

Η έκδοση 0.3.1 εμφάνισε `origin_proof_rejected_no_write` κατά την υποβολή
του πράσινου κουμπιού. Η 0.3.2 ελέγχει με ασφαλείς, μη ευαίσθητες κατηγορίες
τις πληροφορίες που φτάνουν στο πρόσθετο μέσω Supervisor Ingress.

## Ασφάλεια

- **Καμία δημιουργία, μεταβολή ή διαγραφή χρήστη** από την 0.3.2.
- Οι βιβλιοθήκες της παλαιότερης δοκιμής μπορεί να παραμένουν στο GitHub,
  αλλά δεν αντιγράφονται στο Docker image και δεν εισάγονται από την εφαρμογή.
- Κάθε έλεγχος δικαιωμάτων εξακολουθεί να απαιτεί trusted Supervisor peer
  και ανεξάρτητη ανάγνωση του Core.
- Ο έλεγχος υποβολής δεν καταγράφει URL, cookies, Origin, Host, token ή user IDs.
- Εμφανίζει **μόνο** τα χαρακτηριστικά `origin`, `fetch_site`,
  `origin_host`, `custom_header`, με προκαθορισμένες τιμές.
- Ο browser χρησιμοποιεί μικρό τοπικό αρχείο JavaScript με αίτημα
  `same-origin`, ελεγχόμενη κεφαλίδα και χωρίς CORS grants. Αν ο browser
  το εμποδίσει, χρησιμοποιείται η απλή φόρμα ως διαγνωστικό fallback.

## Ελεγχόμενο live QA

1. Ενημερώστε **μόνο** το προσωρινό Smart Pro Access Preflight — QA σε 0.3.2.
2. Αφήστε τις επιλογές auto start, watchdog, auto update OFF.
3. Εκκινήστε και ανοίξτε ως διαχειριστής.
4. Πατήστε μόνο **Έλεγχος υποβολής χωρίς δημιουργία χρήστη**.
5. Στείλτε screenshot με τις πέντε μη ευαίσθητες ενδείξεις.
6. Μην κάνετε άλλη ενέργεια και μην κοινοποιείτε την αληθινή διεύθυνση
   Ingress, cookies ή credentials.

Αν ο browser εμφανίζει `browser_fetch_failed_no_write`, κρατήστε μόνο
αυτόν τον κωδικό. Δεν χρειάζεται πρόσβαση στα DevTools.

Δεν έχουμε ακόμη αποδείξει την ασφαλή λειτουργία **write POST** ή την
αυτόματη δημιουργία χρήστη σε πραγματικό Home Assistant.

# Smart Pro Access Preflight — QA 0.3.3

**ΜΟΝΟ στη φρέσκια δοκιμαστική εγκατάσταση Home Assistant. Ποτέ στην παραγωγή.**

Το 0.3.2 live QA επιβεβαίωσε `request_metadata_observed_no_write`, `origin: valid`,
`origin_host: same`, `custom_header: yes` και `fetch_site: missing`.

## 0.3.3 — Προστατευμένη δοκιμή δημιουργίας και άμεσης διαγραφής

- Διατηρεί ανεξάρτητο έλεγχο ταυτότητας από Supervisor Ingress **και** Core.
- Το πρώτο πράσινο κουμπί παραμένει μόνο διαγνωστικό: χωρίς user writes.
- Το δεύτερο μπλε κουμπί θα επιχειρήσει πραγματική δημιουργία και άμεση διαγραφή **μόνο μετά** από πληκτρολόγηση `ΔΟΚΙΜΗ`, έγκυρη έγκριση μίας χρήσης (180s), νέα επιβεβαίωση Core admin, ακριβές Origin/Host, custom browser header και JSON fetch. Το ελλείπον `Sec-Fetch-Site` δεν αποτελεί blocker· εάν υπάρχει μη επιτρεπτή τιμή απορρίπτεται.
- Δεν υπάρχει ενεργή απλή HTML POST διαδρομή για user writes. Χωρίς JS ή με παλιά εξωτερική υποβολή, απορρίπτεται.
- Ο προσωρινός non-owner admin ονομάζεται `Smart Pro QA TEMP NO LOGIN …`, χωρίς username ή password. Επιβεβαιώνεται και διαγράφεται αμέσως.
- Δεν συνδέεται με Portal, Tunnel, Managed Support ή κανονικό Smart Pro System.
- Μόνο μία προσπάθεια ανά εκτέλεση του πρόσθετου. Προηγείται Core users inventory και απαγόρευση επόμενης δημιουργίας αν υπάρχει υπολειπόμενο QA account.

## Πρώτο live QA με τη 0.3.3 — ΧΩΡΙΣ writes

1. Ενημέρωση μόνο του QA πρόσθετου στο δοκιμαστικό HA, Start on boot, Watchdog και Auto update OFF.
2. Ως διαχειριστής άνοιξε την οθόνη, πάτησε **μόνο το πράσινο** κουμπί read-only probe, και στείλε screenshot.
3. **ΜΗΝ πατήσεις το μπλε κουμπί** και μην πληκτρολογήσεις `ΔΟΚΙΜΗ` μέχρι να επιβεβαιωθεί το πρώτο αποτέλεσμα.
4. Απλός `Smart Pro QA User` πρέπει να απορρίπτεται χωρίς να βλέπει φόρμα.
5. Μόνο μετά από συνεννόηση γίνεται η μία ελεγχόμενη προσπάθεια δημιουργίας/διαγραφής, και *υποχρεωτικά* χειροκίνητος έλεγχος **Ρυθμίσεις → Άτομα → Χρήστες**, είτε το αποτέλεσμα είναι PASS είτε όχι.

Αν το αποτέλεσμα είναι εκτός του `qa_account_created_verified_deleted` ή ο browser διακοπεί, **μην ξαναπατήσεις το κουμπί, μην επανεκκινήσεις** και έλεγξε τυχόν λογαριασμό `Smart Pro QA TEMP NO LOGIN …`. Η απουσία password σημαίνει πως δεν υπάρχει κανονικό login, όχι ότι μπορούμε να αφήσουμε την εγγραφή.

## Ασφάλεια

Το `homeassistant_api: true` περιορίζεται στο QA πρόσθετο· το Core access token παραμένει εντός container, δεν μεταφέρεται ή εμφανίζεται. Οι προστατευμένες WebSocket εντολές περιορίζονται σε `config/auth/list`, `config/auth/create`, `config/auth/delete`. Δεν υπάρχει provider credentials creation. Σε αβεβαιότητα ως προς την έκβαση απαιτείται χειροκίνητος έλεγχος χρηστών.

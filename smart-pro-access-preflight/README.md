# Smart Pro Access Preflight — QA 0.4.0

**ΜΟΝΟ στη φρέσκια δοκιμαστική εγκατάσταση Home Assistant. ΠΟΤΕ σε παραγωγή.**

## Τι αποδείξαμε

Η προηγούμενη έκδοση 0.3.3 πέρασε πραγματική δοκιμή Home Assistant: ο
διαχειριστής εγκρίθηκε, ο μη διαχειριστής αποκλείστηκε, μια εφάπαξ
Core `config/auth/create` δημιούργησε δοκιμαστικό admin χωρίς credentials,
και το `config/auth/delete` τον διέγραψε με επιβεβαίωση
`qa_account_created_verified_deleted`. Δεν παρέμεινε QA TEMP λογαριασμός.

## Τι κάνει η 0.4.0

Με χωριστή ρητή εντολή διαχειριστή δημιουργεί **έναν πραγματικό, μόνιμο στον
Home Assistant χρήστη διαχειριστή** με ακριβές όνομα:

`Smart Pro QA RETAINED NO LOGIN`

Ο νέος χρήστης είναι μη-owner, ανήκει στο `system-admin`, είναι `local_only`
και ΔΕΝ έχει username, password, credentials ή login. Η εγγραφή του παραμένει
στο Home Assistant όταν κλείσει ή ενημερωθεί το QA πρόσθετο. **Δεν αποτελεί
ακόμη λειτουργική απομακρυσμένη πρόσβαση Smart Pro.**

Η δεύτερη χωριστή ενέργεια διαγράφει μόνο τον ακριβή δοκιμαστικό λογαριασμό,
ύστερα από νέα, διαφορετική έγκριση διαχειριστή. Αν βρεθούν διπλότυπα,
συνημμένα credentials, αλλαγμένα δικαιώματα ή άγνωστη κατάσταση, η αυτόματη
διαγραφή μπλοκάρεται και απαιτείται χειροκίνητος έλεγχος.

Ούτε ο προσωπικός κωδικός του πελάτη ούτε κανένας κωδικός του Smart Pro
ζητείται ή μεταφέρεται. Η εφαρμογή **δεν συνδέεται με Portal, MeshCentral,
Managed Support, Smart Pro System ή Tunnel**. Δεν προσθέτει credentials.

## Live QA — checkpoints, ένα κάθε φορά

1. Ενημέρωσε μόνο το **Smart Pro Access Preflight — QA 0.3.3 → 0.4.0**
   στο TEST HA. Κράτησε Start on boot / Watchdog / Auto update OFF.
2. Άνοιξε το Web UI ως διαχειριστής. Επιβεβαίωσε την ταυτότητα και την
   ένδειξη **δεν υπάρχει ο ειδικός δοκιμαστικός λογαριασμός**. Στείλε
   screenshot. **Μην πατήσεις δημιουργία ακόμη.**
3. Σε χωριστό ελεγχόμενο βήμα, ελέγχουμε την καρτέλα Χρήστες για να μη
   υπάρχει `Smart Pro QA RETAINED NO LOGIN` ή `Smart Pro QA TEMP NO LOGIN …`.
   Τότε πληκτρολογούμε `ΔΗΜΙΟΥΡΓΙΑ` και πατάμε ΜΙΑ φορά το μπλε κουμπί.
   Αναμενόμενο: `qa_retained_admin_created_no_login`.
4. Ελέγχουμε στην καρτέλα Χρήστες ότι υπάρχει ακριβώς ένας
   `Smart Pro QA RETAINED NO LOGIN`, χωρίς username ή password.
   Σταματάμε / ξαναξεκινάμε μόνο το QA πρόσθετο και επιβεβαιώνουμε ότι
   ο λογαριασμός παραμένει. Δεν αλλάζουμε χρήστη ή δικαιώματα.
5. Σε χωριστό βήμα, με νέα έγκριση, πληκτρολογούμε `ΑΝΑΚΛΗΣΗ` και
   πατάμε ΜΙΑ φορά το κόκκινο κουμπί. Αναμενόμενο:
   `qa_retained_admin_revoked_verified`.
6. Ελέγχουμε ότι αφαιρέθηκε μόνο ο δικός μας QA λογαριασμός, ενώ οι
   υπάρχοντες χρήστες (ιδίως `Smart Pro QA User`, `smartproqa 9` και
   `Supervisor`) παραμένουν αμετάβλητοι.

**Στο πρώτο checkpoint κάνουμε ΜΟΝΟ έλεγχο εμφάνισης.** Κάθε πραγματική
δημιουργία ή ανάκληση θα γίνει ξεχωριστά και με ρητή συνεννόηση.

## Προστασίες

- Ακριβής peer Supervisor Ingress και identity headers, ανεξάρτητο fresh
  Home Assistant Core `config/auth/list` σε κάθε ενέργεια.
- HTTPS/HTTP Origin πρέπει να ταιριάζει ακριβώς με Host, χωρίς αποδοχή
  cross-site `Sec-Fetch-Site`· το ελλείπον metadata που παρατηρήθηκε στο
  0.3.2 δεν θεωρείται από μόνο του απόδειξη ή πρόβλημα.
- JSON POST με ειδική κεφαλίδα JavaScript, στενά καθορισμένο route και
  one-time user-bound 180-second consent token. Διαφορετική επιβεβαίωση
  και χρήση token για CREATE / REVOKE. Κάθε ενέργεια το πολύ μία φορά ανά
  εκτέλεση εφαρμογής.
- Χωρίς αυθαίρετο όνομα, ρόλο, ID ή εντολή από browser.
- Δεύτερη ανάγνωση από Core μετά το write· δεν εμφανίζονται user IDs,
  cookies, tokens, λίστες χρηστών ή προσωπικά δεδομένα.
- Δεν υπάρχουν Home Assistant auth provider credential commands.
- **Αν διακοπεί η επικοινωνία στο write, το αποτέλεσμα μπορεί να είναι
  αβέβαιο.** Σταμάτα και έλεγξε τη λίστα χρηστών. ΜΗΝ ξαναπατήσεις το κουμπί.

## Όριο αυτού του milestone

Η 0.4.0 επαληθεύει τη διατήρηση/ανάκληση εγγραφής admin, **όχι πραγματικό
login της Smart Pro**. Για το επόμενο στάδιο χρειάζεται ξεχωριστό ασφαλές
μοντέλο δημιουργίας credentials, κατοχής/κρυπτογράφησης, περιστροφής,
μεταφοράς προς Smart Pro χωρίς Portal plaintext, revocation και audit.
Τυχόν activation θα γίνει μόνο μετά από έγκριση, με νέο ελεγχόμενο QA.
